# foot for macOS: notes for AI assistants

A native macOS port of the foot terminal emulator. foot's terminal core
is upstream code; the macOS platform layer (AppKit, Core Animation,
CoreText, kqueue) lives in `macos/`.

## Build and test

```sh
make deps       # brew install meson ninja bison
make build      # debug build in build/ (configures it the first time)
make test
make smoke      # foot in real windows (macos/smoke-test.py)
make sanitize   # the tests and the smoke test, with ASan and UBSan
make linux      # footd on Linux: built and tested in a container (macos/linux.sh)
make run        # ./build/macos/foot
make release    # optimized build and foot.app in build-release/
make pgo        # the same, with PGO like releases (macos/pgo.sh; a window opens)
make bench      # foot against kitty and Ghostty (macos/bench/README.md)
make dist       # universal, notarized foot.app (NOTARY_PROFILE=...)
make publish    # a release: GitHub, Sparkle, Homebrew (.github/RELEASING.md)
```

`make` lists all commands. The `Makefile` only wraps meson and ninja
(`meson setup build --native-file macos/native.ini`, `ninja -C build`,
`meson test -C build config`); it is the port's own file, and isn't in
upstream. The help screen's banner is drawn by `macos/banner.sh`.

The application icon is generated by `macos/icon/make-icon.py` (`make
icon`, needs `rsvg-convert`); the generated `foot.svg` and `foot.icns`
are committed.

Debug builds run foot's unit tests (`UNITTEST` blocks) at startup.

Persistent sessions: the programs run in footd (`macos/footd.c`), a
daemon foot starts; a window's terminal reads footd's socket instead of
a PTY (`macos/session.c`), and the windows' layout is kept by footd
(`macos/session-layout.m`). footd keeps each session's state in foot's
terminal core without a window (`macos/headless.c`), and sends it to a
window that attaches (`macos/snapshot.c`). Only foot as the application
uses sessions; tests enable them with `FOOT_SESSIONS_SOCKET=<path>` (a
footd of their own). `meson test sessions` checks the snapshots
(`test-sessions --dump COLS ROWS INPUT` shows a terminal's state),
`meson test footd` footd itself, `macos/smoke-test.py build/macos
sessions` the whole thing with windows. footd builds on Linux too (for
servers foot reaches over SSH): `macos/meson.build` builds only footd
there, the core's macOS parts have stand-ins in `macos/compat-linux/`,
and `make linux` checks it.

## Rules

- **Keep upstream merges trivial.** Read `macos/UPSTREAM.md` before
  changing any file outside `macos/`. New code goes in `macos/`; changes
  to upstream files must be minimal and local. Never reformat upstream
  code.
- **Native only.** No Wayland/X11 shims, compositors or emulation
  layers. Use AppKit, Core Animation, CoreText and kqueue directly.
- **Performance matters.** Rendering stays on the CPU (pixman), with
  zero copy presentation (IOSurfaces); nothing may poll or wake up
  while idle.
- **Upstream syncs** are merges (`macos/sync-upstream.sh`), never
  rebases. Resolve conflicts as described in `macos/UPSTREAM.md`.
- **Sanitizers:** `make sanitize` stays clean. `macos/ubsan.supp` is for
  third-party and upstream code; fix what it finds in `macos/`.
- **Testing input:** never send global keystrokes (e.g. with
  `osascript`/System Events); they end up in whatever application the
  user is working in. Post events to foot's PID only
  (`CGEventPostToPid()`).
